# 三产品互消费迁移核对（基于仓库 semver 实算）

## 小清单（本核对使用的一组示例数据）

消费方向（消费者读生产者输出）：`B 读 A`、`C 读 B`、`A 读 C`，构成环。
格式按 SemVer 版本化：F1=`1.0.0`（旧）、F2=`2.0.0`（新）、F3=`3.0.0`（仅 C 候选版可写）。

| 产品 | 版本 | 可读格式区间 | 可写格式 | 角色 |
|------|------|--------------|----------|------|
| A | 1.4.2 | [1.0.0, 2.0.0) | F1 | 现网旧版 |
| A | 2.0.0 | [1.0.0, 3.0.0) | F1, F2 | 候选：宽容读 + 双写，当迁移桥 |
| B | 1.6.0 | [1.0.0, 2.0.0) | F1 | 现网旧版 |
| B | 2.1.0 | [2.0.0, 3.0.0) | F2 | 候选：移除 F1 读，只写 F2 |
| C | 1.5.1 | [1.0.0, 2.0.0) | F1 | 现网旧版 |
| C | 3.0.0 | [2.0.0, 4.0.0) | F2, F3 | 候选：移除 F1 读 |

保留要求：F1 旧记录保留 **7 天**；最后一条 F1 记录产生于 2026-11-13。

所有“可读区间是否含某格式”的判断都由本仓库 `semver.Version` 比较实算，
运行：`python migration_audit/checklist.py`（退出码 0 表示全部断言通过）。

## 可执行迁移顺序（逐步替换，每步三条边均被核对为 OK）

| 步骤 | 日期 | 部署动作 | 各产品输出 pin | 核对结论 |
|------|------|----------|----------------|----------|
| 0 | — | 现网基线 A1/B1/C1 | 全 F1 | 三条边共用 F1，相容 |
| 1 | 即刻 | 仅替换 A：1.4.2 → 2.0.0 | A 仍 pin **F1**（双写但不切），B/C 仍 F1 | A2 能读 C1 的 F1；A2 写 F1 给 B1，不断流 |
| 2 | **不早于 2026-11-20** | 同窗口替换 B→2.1.0、C→3.0.0，同时 A 输出 pin 翻到 **F2** | 全 F2；C 禁止选 F3（B2 读区间到不了 3.0.0） | 三条边共用 F2，相容 |
| 3 | 2026-11-21 起 | 无部署；F1 保留期满，归档/删除 F1 记录，A2 关闭 F1 读写通道 | 全 F2 | 数据清理，链路无 F1 依赖 |

为什么 B、C 不能各自先动（脚本已实算 FAIL）：
- 先换 B：A1 只写 F1，而 B2 读区间 `[2.0.0,3.0.0)` 无 F1 → A→B 断；B2 写 F2 而 C1 读不了 → B→C 断。
- 先换 C：B1 写 F1 而 C2 读不了 → B→C 断；C2 最低写 F2 而 A1 读不了 → C→A 断。
- 即使 A 已先灰度，B、C 仍互相卡死（B2 的 F2 C1 读不了；C2 要的 F2 B1 给不了），必须同窗口换。

## 若只允许一次同步切换

枚举全部 7 个同换子集后，唯一可行且直达全目标的组合是 **{A, B, C} 三家同换**：
任何留下旧版的子集都存在“旧版只写 F1 × 新版不读 F1”的断链。

同换时被旧记录卡住的产品与记录：
- **B@2.1.0**：被 A1/A2 灰度期写出的 F1 输入与回溯存量卡住（B2 读区间不含 1.0.0）。
- **C@3.0.0**：被 B1 写出的 F1 输入与回溯存量卡住（C2 读区间不含 1.0.0）。
- 切换日不得早于 **2026-11-20**（最后 F1 记录 2026-11-13 + 7 天）；窗口内的 F1 记录
  须自然到期或先做 F1→F2 前向转换，否则 B2/C2 解析即失败。
